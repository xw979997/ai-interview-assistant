# AI 面试助手（本地离线版）

实时捕获面试官的语音 → 本地 Whisper 识别成文字 → 本地大模型（Qwen2.5-3B，经 Ollama 运行）流式生成可以直接照着说的中文答案 → 置顶悬浮窗显示。

**全程离线、免费、不需要任何 API Key、不上传任何数据。**

## 工作原理
- 用 Windows WASAPI **loopback（回环）** 抓取「系统输出声音」，也就是面试官通过你扬声器/耳机说的话（戴耳机也能抓到）。
- 简单能量 VAD 把语音切成一句一句，停顿约 0.8 秒就认为一句说完。
- 本地 `faster-whisper` 把这句话转成中文文字。
- 本地 `Ollama` 跑 Qwen2.5-3B 中文模型，流式生成第一人称的中文回答，结合你在 `context.txt` 里写的简历/岗位资料。

## 组件
- 语音识别：`faster-whisper`（Python 库，CPU int8，默认 base）。
- 大模型：`Ollama` + `Qwen2.5-1.5B-Instruct`（默认，速度快）。Ollama 自带 CPU 运行时分发，
  无需 AVX-512，普通 CPU 即可运行；通过其 OpenAI 兼容接口（http://localhost:11434/v1）调用。
  想要答案更有深度，可换 `qwen2.5:3b-instruct`（见下文）。

## 环境要求（在干净电脑上部署）
- **Windows 10/11**。
- **Python 3.10+（建议 3.12）**：先自行安装，安装时勾选 “Add Python to PATH”。
  没装的话：到 https://www.python.org/downloads/ 下载，或命令行 `winget install Python.Python.3.12`。
- **联网**：仅首次安装需要联网（下载依赖、Ollama、模型，约 1.2GB）；装好后日常使用可完全离线
  （联网检索功能除外）。
- 建议 8GB 以上内存、较新的 CPU（纯 CPU 运行，无需显卡）。
- Ollama 会由 `setup.bat` 自动安装，无需手动装。

## 在干净电脑上一键部署
1. `git clone` 本仓库（注意：仓库不含模型文件，会在下一步自动下载）。
2. 确认已装好 Python（见上面「环境要求」）。
3. **双击 `setup.bat`**：自动完成全部环境部署——
   装 Python 依赖、装并启动 Ollama、拉取语言模型、下载语音识别模型。首次约几分钟（取决于网速）。
4. 打开 `context.txt`，把里面的示例换成你自己的真实简历内容。
5. **双击 `run.bat`** 启动。等状态显示「聆听中…（模型已就绪）」即可。

> 所有 `.bat` 都会自动探测 Python（py 启动器 / python / 常见安装路径），无需改任何路径。
> Ollama 服务由 `run.bat` 自动确保在后台运行。

## 自测：用语音考官测试软件
想在没有真人面试时测试效果，可以用内置的"语音考官"：它用系统声音朗读面试问题，
助手会像真实面试一样抓取并作答。
1. 先双击 `run.bat` 启动助手，等显示『聆听中…（模型已就绪）』。
2. 再双击 `speak_test.bat`，它会逐题朗读（每题之间默认停顿 35 秒让助手作答）。
3. 看助手窗口是否正确识别并回答。
- 可选参数：`speak_test.bat --gap 40 --delay 8`（每题停顿 40s、开始前倒计时 8s）。
- 问题列表在 `speak_test.py` 顶部的 `QUESTIONS` 里，可自行增删。
- 注意：测试时别让电脑同时播放音乐/视频，否则会和朗读混在一起影响识别。

## 界面说明
- **面试官问题**：识别出的问题。
- **建议回答**：本地大模型生成的答案，逐字流式蹦出来，可直接照着说。
- **🎧 声音来源**：下拉选择抓取哪个输出设备（默认设备 / 扬声器 / 耳机），**可随时切换、立即生效**；中途插拔耳机后点旁边的 🔄 重新扫描设备。
- **🌐 联网:开/关**：开关联网检索（开=每题先搜对口案例再作答，更丰富但慢几秒；关=纯本地更快）。
- **🎯 目标岗位**：直接在输入框里填你要面的岗位名（如 `产品经理`、`Java后端开发`），
  回车或点「应用」即生效——助手会**立刻按这个岗位的专业知识作答、联网检索也聚焦该岗位**；
  留空则跟着问题本身走。填过的岗位会被记住（写入 config），下次启动自动带上。
- **模式:只答最新 / 模式:每题都答**：点击切换回答模式。
  - **只答最新**（默认）：面试官问得急时，自动只回答最近的那一题、跳过来不及处理的旧问题，保证不掉队。
  - **每题都答**：按顺序逐题作答、一题不漏（CPU 较慢时会排队，可能稍有延迟）。
- **⏸ 暂停聆听 / ▶ 继续聆听**：暂停或恢复抓声音（快捷键 Ctrl+Space）。
- **📌 置顶**：开/关窗口置顶。
- **🗑 清空**：清空当前问答。
- **手动提问**：底部输入框直接打字提问（最高优先级，会先于聆听到的内容作答）。

## config.json 配置项
| 字段 | 说明 | 默认 |
|------|------|------|
| `backend` | `local`=本地离线；`openai`=云端（需 Key） | `local` |
| `language` | 识别 / 回答语言 | `zh` |
| `whisper_model` | 识别模型：tiny/base/small/medium，越大越准越慢 | `base` |
| `ollama_url` | 本地 Ollama 地址 | `http://localhost:11434` |
| `ollama_model` | Ollama 中的模型名 | `qwen2.5:1.5b-instruct` |
| `max_tokens` | 单次回答最大长度 | `280` |
| `temperature` | 生成温度，越低越忠于简历、越少编造 | `0.4` |
| `threads` | CPU 线程数，0=自动 | `0` |
| `silence_seconds` | 停顿多少秒算一句说完 | `0.6` |
| `max_utterance_seconds` | 单句最长时长 | `20` |
| `min_utterance_seconds` | 短于这个时长的声音忽略 | `0.6` |
| `energy_threshold` | 声音门限，0=自动校准；环境吵可手动调大 | `0.0` |
| `loopback_device` | 指定回环设备名（关键词匹配），留空=默认扬声器 | 空 |
| `answer_mode` | 回答模式：`latest`=只答最新；`all`=每题都答 | `latest` |
| `target_role` | 目标岗位名（面试岗位和简历不同时填，作答/检索更聚焦该岗位） | 空 |
| `web_search` | 是否每题先联网检索案例再作答（需联网，略慢） | `true` |
| `web_results` | 联网检索保留的结果条数 | `3` |
| `web_timeout` | 联网检索超时秒数（超时则跳过，不影响作答） | `12` |
| `web_query_hint` | 检索时额外附加的关键词（一般留空，跟着问题走即可） | 空 |

## 答案策略：自动区分「专业题」和「个人题」
助手每收到一个问题，会先用模型**快速判断这是「考专业知识」还是「问你本人经历」**，再决定怎么答：
- **专业题 / 技术题 / 与岗位相关的题**（如“解释数据库索引”“什么是测试左移”“怎么做需求优先级”）：
  **完全基于该领域的专业知识作答，绝不硬套你的简历**，所以面试和简历不相关的岗位也能答得专业准确。
- **个人题 / 背景题**（如“自我介绍”“你哪个学校”“你的优缺点”“为什么离职”）：
  才会结合你的简历来答，硬事实（学校、专业、公司、职务、年限）严格按简历、不编造。
- 这样既解决了“无关问题被往简历上带偏”的问题，又保证个人信息准确。
- **如果你提前知道要面的岗位**（尤其和简历不同），在 `config.json` 的 `target_role` 填上岗位名
  （如 `产品经理`、`Java后端开发`）或用界面「🎯 目标岗位」框，助手会优先按该岗位作答、联网检索也更聚焦。

## 联网检索（结合最新案例作答）
开启后（默认开），助手每收到一个问题会先联网搜索**与问题对口**的案例/最佳实践，
再把搜到的内容交给模型，生成更有深度、有行业案例支撑的答案（检索跟着问题走，不绑定任何固定行业）。
- 走系统代理联网，约多花 3-5 秒；纯本地不联网时答案更快。
- 界面顶部「🌐 联网:开/关」按钮可随时切换；也可在 `config.json` 把 `web_search` 设为 `false` 关闭。
- 联网失败/超时会自动跳过，回退为纯本地作答，不会卡住。

## 云端大模型（更快更聪明，推荐）
本地 1.5B 模型在纯 CPU 上较慢、也没那么聪明。可以把**答案生成**交给云端大模型
（语音识别仍在本地、不上传音频），答案又快又好（实测每题约 3 秒）。
1. 申请一个 API Key（推荐 DeepSeek：https://platform.deepseek.com ，便宜、质量高）。
2. 在项目根目录新建 **`secrets.json`**（此文件已被 git 忽略，不会上传），内容：
   ```json
   { "cloud_api_key": "sk-你的Key" }
   ```
3. 在 `config.json` 里设置：
   ```json
   "chat_provider": "cloud",
   "cloud_base_url": "https://api.deepseek.com/v1",
   "cloud_model": "deepseek-chat"
   ```
   - 通义千问：base_url 用 `https://dashscope.aliyuncs.com/compatible-mode/v1`，model 用 `qwen-plus`。
   - OpenAI：base_url 用 `https://api.openai.com/v1`，model 用 `gpt-4o-mini`。
4. 双击 `run.bat` 即可（云端模式无需下载/常驻本地大模型）。
- 想换回纯本地：把 `chat_provider` 改回 `local`。
- API Key 只存在本地 `secrets.json`，不会进入 git 仓库。

## 速度 / 质量调节（纯本地档）
本地默认用 `base` 识别 + `qwen2.5:1.5b-instruct` 生成 + 回答上限 170 字。
- **想答案更准/更有深度**：用上面的**云端大模型**（最推荐），或本地换 `qwen2.5:3b-instruct`。
- **想识别更准（稍慢）**：把 `whisper_model` 改成 `small` 或 `medium`。
- **想答案更长**：调大 `max_tokens`（纯 CPU 上越长越慢；云端不受影响）。
- **想要更高质量（联网）**：换更大的 Ollama 模型 `ollama pull qwen2.5:7b`，把 `ollama_model` 改成它。

## 想用云端 OpenAI（可选）
把 `config.json` 的 `backend` 改成 `openai`，并填 `openai_api_key`（或设环境变量 `OPENAI_API_KEY`），效果更好但需联网、收费。

## 常见问题
- **提示连不上 Ollama**：确认 Ollama 在运行（开始菜单启动 Ollama，或命令行 `ollama serve`）。
- **识别不到声音**：确认面试软件的声音从「默认播放设备」出来；用了虚拟声卡就把设备名填到 `loopback_device`。
- **总被环境噪声触发**：把 `energy_threshold` 调大（如 0.01）。
- **答案蹦得慢**：纯 CPU 运行正常现象，已用流式逐字输出；可换更小模型或减小 `max_tokens`。
- **第一次启动较慢**：启动时会预热模型约 1 分钟（状态栏会提示），属正常；之后每个问题约 15~25 秒出全文，首字 1~2 秒就开始蹦。建议面试前先开好程序等它就绪。
- **乱码**：请用 `run.bat` 启动（已设置 UTF-8）。
